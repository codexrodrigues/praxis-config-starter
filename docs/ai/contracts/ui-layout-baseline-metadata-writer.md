# Correlated baseline metadata in the lifecycle writer

This beta Java SPI change adds required `UiLayoutBaselineMetadataSeed` to every `UiLayoutDraftWorkspaceSeed.TargetSeed`. Native B0 and its actual structural input must come from the same host producer observation. `UiLayoutBaselineMetadataAdmission` separately admits producer/publication, structural operation and content, native B0 correlation, normalizer/projector artifacts and effective policy. An identity string or digest is not sufficient authorization. There is no compatibility constructor or latest-schema fallback.

The seed is server-only, not an HTTP DTO. Source is a sealed union: OperationSource identifies exact resource/operation/request-or-response schema and uses SchemaProjection with actual normalization/projection artifacts; NativeDocumentSource identifies a native document and immutable revision/publication and uses NativeIdentity. Both require service/producer/publication and mandatory rawInputText. Observation pins actor, administrative unit, context version, policy/ref revision and declared time. Never infer origin from labels or editor schemaVersion.

## Create and replay

The canonical writer resolves the authenticated host invocation, takes the existing creation lock and enters the Config TransactionOperations callback. It re-resolves the full invocation before producer capture, before draft persistence and at final read/return. Equality covers actor/tenant/unit/environment/context/root/full composition, not just the caller context string. Host providers must support final revalidation without leaking an operational transaction/resource into Config writes.

Fresh creation rejects unsafe JSON/foreign nodes before workspace serialization or content admission; validates native baselines, observation scope and host metadata admission; saves and flushes the draft; seals captures against that draft's exact B0/source/descriptor; appends to Config JDBC with the writer TransactionStatus; rereads and compares stored captures before returning. Failures mark the Config transaction rollback-only. JPA and JDBC must share the Config datasource/transaction. Schema/body limits and immutable storage constraints are documented in the [storage boundary](ui-layout-metadata-capture-storage-internal.md).

Idempotent replay never invokes the source or append. It projects the pinned workspace and reads exact stored captures under current admission/context. Missing historical metadata denies replay; it is never backfilled from mutable api_metadata. Admission and full context are rechecked before returning. This proves only the checked observation boundary: there is no policy/version fencing token or atomic producer transaction spanning external schema publication.

## Host composition and limits

Writer autoconfiguration now requires the metadata admission bean and `configNamedParameterJdbcTemplate` in addition to the existing source/structure/invocation/policy/transaction dependencies. The public factory takes Config JDBC and metadata admission; production always composes the internal Config JDBC store. The internal storage port exists for isolated tests and is not a host SPI or alternative store.

Every target requires a genuine admitted origin; mixed native/operation compositions use the same writer/store/replay and quota. NativeIdentity verifies that parsed input equals B0 with object and array order preserved, allowing JSON whitespace variation. It is not a provenance exemption or permission grant. Native transformations remain unsupported until an explicit reproduction contract exists. No selector exemption, nullable evidence or fabricated GET/path/resource is accepted. Unit fixtures prove orchestration only.

The capture/store boundary owns its JSON configuration: host leniency cannot permit comments, single quotes, unquoted names, trailing commas or non-finite numbers. Explicit null properties and insertion order are retained on parsing and persistence, irrespective of host tree serialization defaults. These checks preserve input identity; they do not establish content authority or full native schema validity.

The beta migration removes concrete Source/Reproduction constructors: use OperationSource/SchemaProjection or NativeDocumentSource/NativeIdentity, and rawInputText in place of rawSchemaText. V67 extends V66 with an explicit origin discriminator and native document identity/revision. Existing operation rows are classified without altering payloads, live metadata lookup or admission exemption. V66 checksum is preserved; apply migrations in sequence. No old Java aliases remain. Native origin requires host admission of document/publication/B0 correlation; a child source cannot attest its parent.

Structural ETag/X-Schema-Hash is also not an immutable publication witness for reproduction. Metadata Starter canonicalizes object keys for that hash, while Core/Table projection can depend on property order. Angular transport currently reads text transiently and retains parsed schema/hash; it does not expose a raw admitted capture to the writer. Producer integration must preserve the exact input used for B0, relevant resolution context and actual producer/normalizer/projector artifact identities. It must verify reproduction before accepting a declaration. No new ETag semantics or metadata endpoint is introduced here.

HTTP receipt/schema/routes remain unchanged and do not contain raw schema, producer/policy or private capture context. GET/readiness/historical services still project their existing native evidence; they do not yet deliver or diagnose the stored metadata. No Table runtime consumes these rows yet. Quickstart still lacks a real producer/admission composition: consumer tests prove boot/classpath and absence of accidental activation, not an accepted operational capture journey.

V66 execution, actual PostgreSQL quota/concurrency/FK/immutability and real JPA/JDBC rollback require an approved existing DB window before publication/activation. No DB/Docker/monitor is started by this change. No field-level upgrade diagnosis, historical attestation, apply authority or release is claimed.

## Producer execution prerequisites

SchemaProjection now requires DocumentAssembly(inputVersion=1, assemblerRef, inputText). It preserves the exact JSON object of all variable full-document inputs separately from rawInputText (the structural schema). Table inputs include native config/projection intent, bindings and any context that changes the assembly. The admitted immutable assemblerRef must identify the entire assembly chain, dependencies and fixed defaults. Config does not reinterpret Table semantics or execute this text: the host must validate its owner-defined format, completeness, authority and exact reproduction. Empty objects are not proof of fixed inputs; only admission of the actual producer/assembler can establish that. Historical verification cannot obtain missing options from current preferences or templates.

This deliberately replaces the two-argument SchemaProjection constructor in the beta SPI; no overload or alias remains. V68 stores assembly_input_version/assembler_ref/assembly_input_text/assembly_input_hash, counting both input texts against the 1 MiB composition quota (each is at most 256 KiB). Strict object JSON, UTF-8, nesting, duplicate-key/trailing-token and hash gates apply to assembly inputs too. Replays use the captured text and current admission; they do not invoke the producer. Legacy operation rows without assembly inputs fail closed; V68 does not backfill them. The NOT VALID constraint preserves existing immutable rows while enforcing completeness on new inserts; validation of all historical rows requires an explicit governance/migration decision, not fabricated inputs. NativeIdentity carries no assembly declaration.

The normalizer can evaluate a declared transform expression while constructing fields (parseFunction uses new Function). It is not an inert parser or a generally safe server verifier for untrusted proposals. The source producer must validate origin, current content authority and the permitted execution boundary before normalizing; CREATE_DRAFT admission and the later metadataAdmission callback alone do not protect earlier producer execution. Do not feed browser-declared expressions/snapshots into a server executor or create an ad hoc Node/HTTP bridge. Use the official admitted artifact/execution boundary with complete inputs. A local source-code probe proves behavior, not a production executor or source publication.
